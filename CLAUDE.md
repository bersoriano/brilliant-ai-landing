# Brilliant AI: notes for Claude

Next.js 15 (App Router), React 19, TypeScript, Tailwind 4 (imported, but styling is plain CSS). The site ships in English (`/`) and Mexican Spanish (`/es`).

## Rules
- **Copy goes through `t()`** (`useLanguage`). English source strings are the keys in `lib/es-MX.json`. Every new literal `t("…")` needs a Spanish entry, or `npm test` fails.
- **CTA labels come from constants:** `PRIMARY_CTA`, `NAV_CTA` (short form), `ONSITE_CTA`, `CRM_CTA`, `WHATSAPP_CTA` in `lib/site.ts`. Never reword them inline.
- **Audience:** the homepage speaks to finance and healthcare only (`HOMEPAGE_INDUSTRIES`). Operations/sales stay in the data and reach the form as "Other".
- **Homepage = conversion page.** Hero (Exhibit 1) → pains (three per sector) → calculator (Exhibit 2) → Services cards → How it works → Trust (short, links `/security`) → Rhino teaser → What we've learned → six FAQs (`HOMEPAGE_FAQS`, the rest on `/services`) → contact. Detail goes on the service pages, not back on the homepage.
- **Services** (`#services`, `components/sections/Services.tsx`, data in `lib/services.ts`): five offers as one set of cards after the calculator, each linking its page (`SERVICES[].path`): `/workflows`, `/agents`, `/custom-crm`, `/custom-erp`, `/custom-software` (data in `lib/software.ts`), plus the `/services` index. Cards keep the old anchors (`#crm`, `#erp`, `#software`). Every page keeps approvals with a named person and repeats the review CTA; the section closes on `PRIMARY_CTA`. Business terms only: a test rejects build-stack and technical names (open-source, model plumbing, the foundations underneath) in the cards and service pages, English and Spanish. A new page needs a `pageFromPath` key, title, description, sitemap and `scripts/verify-seo.cjs` entry (a test checks them).
- **Nav:** Services (a disclosure listing `SERVICES`), How it works, Security, Blog, `NAV_CTA` ("Book a review"). Service pages use the full `Navbar`; `/security`, `/about` and the sector pages use the slim `PageHeader`.
- **Positioning: operator, not consultancy.** Authority comes from how the work runs (exceptions, approvals, measurement), not from advisory language. No "AI strategy", roadmaps, transformation programs, change management or readiness/maturity framing, and never describe Brilliant as a consultancy ("consulting arm", "consultoría") (`CONSULTANCY_PHRASES` in `lib/insights.ts`; a test enforces it in homepage copy, the dictionary and posts). No team bios or credential lists. Authority content links back to the 20-minute review, never competes with it. **Link, don't lecture:** the homepage shows a rule in one line and links the note that explains it; no explanatory paragraphs on the homepage (a test keeps "What we've learned" to three one-line rules, each linking a note). Service pages list their notes with `getNoteLinks`.
- **Notes linked from the homepage** ("What we've learned", the calculator), the service pages and the finance/healthcare pages are registered in `INSIGHTS` (`lib/insights.ts`); a test keeps each one published in both languages.
- **Mexican Spanish uses *tú*** with the visitor ("ustedes" when the visitor addresses us: "Ayúdennos"). A test rejects *usted* and Spain-only forms in `lib/es-MX.json`. Use Mexican nouns: CFDI, OC, RFC, preautorización, aseguradora, iguala, junta.
- **Currency follows the language:** USD in English, MXN in Spanish (no FX conversion; editable defaults per currency).
- **Honesty:**
  - Workflows are examples; tool names are potential integrations.
  - The case study renders only via `shouldRenderCaseStudy`.
  - The ROI is capacity-first (see `lib/roi.ts`).
  - Never invent stats, clients or certifications. Security copy describes a process the client controls (`/security`); it never claims SOC 2, HIPAA attestation, or CFDI/MXN invoicing.
  - Employer names (BCG, BofA, Merrill Lynch, Banorte, BNY Mellon, Accenture, IBM) live only on `/about` with the "not clients" hedge; a test keeps them off the homepage.
  - Haab Calendar (where every booking CTA lands) is Brilliant's own product, never a client or partner (a test enforces it). The custom software offer (`/custom-software`) shows it through its recorded demo (the page's Exhibit 1, fictional patient, "Sample data") and lists only features Haab ships.
  - Document scenes (`lib/scenes.ts`) are illustrative: invented names and numbers, labelled "Sample data" in the exhibit header.
  - The custom CRM offer (homepage card `#crm`, the `/custom-crm` landing, data in `lib/crm.ts`) is white-label: `/custom-crm` says "open-source foundation" (nothing else does) and never names the project, here or anywhere in this public repo (a test enforces it). List only features that foundation ships. The base-plan price lives in `CRM_PRICE`, set per currency (no FX conversion).
  - The custom ERP offer (homepage card `#erp`, the `/custom-erp` landing, data in `lib/erp.ts`) is white-label the same way: never name the system underneath, here or anywhere in this public repo (a test enforces it). List only features it ships. The starting price lives in `ERP_PRICE` (same level as the CRM today), set per currency. Spanish ERP copy doesn't promise CFDI invoicing ("cuentas por cobrar y por pagar", not "facturación").
- **Blog posts** are MDX in `content/posts/<slug>/en.mdx` + `es.mdx` (both required, same `date` and `draft`). Frontmatter: `title`, `description`, `date` (YYYY-MM-DD), optional `updated`, `draft`. Drafts render in dev only. Start the body with a paragraph (the page renders the `h1`); end with a `## Next step` that invites the reader to the 20-minute review, then `<BookReview />` (the booking button with `PRIMARY_CTA`; the page adds no other, and a test requires exactly one per post). Images go in `public/blog/<slug>/`, never remote. `npm test` compiles every post and applies the honesty and *tú* rules to it. Reader: `lib/posts.server.ts`; pages: `app/blog/`. Linked from the nav and the footer (the homepage has no blog teaser). `/custom-crm` links `CRM_POST_SLUG` (`lib/crm.ts`) and `/custom-erp` links `ERP_POST_SLUG` (`lib/erp.ts`); a test keeps both published. Draft new posts with `/new-post <topic>` (`.claude/commands/new-post.md`).
- **Design system (B5 "Ink"):**
  - Tokens, type classes and primitives live in `app/globals.css`; section layout goes in co-located `*.module.css`.
  - Fonts are local via `lib/fonts.ts`; don't add third-party font or image requests. Video is self-hosted too: compressed MP4 + poster + English and Spanish captions in `public/video/`, never a third-party embed.
  - Radius 0, one teal accent, no gradients or shadows.
  - Logo: the Aurora prism lockup (`public/brand/`, via `Brand`/`BrandLogo` in `components/ui/Icon.tsx`; favicons and manifest in `app/`). Its gradient lives only inside the mark, never in UI. The lettering reads "brilliant": don't add "AI" to the mark (`SITE_NAME` stays "Brilliant AI" in text).
  - Type: Bricolage Grotesque (display, weight 600, no italic) over Geist (body) and Geist Mono (labels). `html` sets `font-synthesis: none`, so `font-style: italic` on display text renders upright; accent phrases (`<em>` in headings) are teal, not slanted. Don't add `-webkit-font-smoothing: antialiased`.
  - Light sections use `.band-paper`: a cool mist ground (`#eaf2f1`) with white `--surface` cards, deep teal accent; it redefines the tokens and every text pair is ≥ 4.5:1 on both. No warm cream "paper". Keep navy for hero, calculator and close.
  - Exhibits are live demos, numbered per page from 1 (see "Live exhibits" in `docs/conversion/NOTES.md`): they end with a `.control` line ("Stays with you", sand = needs a person), and motion only comes from `useFirstView`/`Reveal`, which show the final state under reduced motion. The one exception is the Haab demo on `/custom-software`, a recorded video: `controls`, `preload="none"`, never autoplay, and one caption track always on in the page's language (iOS stalls on play when every track is off).
  - Spec: `docs/redesign/B5-SPEC.md`.
- **Keep a11y behavior:** tab keyboard handling, `aria-pressed` / `aria-selected`, native `<details>`, skip link, focus return in the mobile nav.
